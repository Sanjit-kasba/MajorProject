# IntraView

IntraView is a mock interview application. The candidate answers interview questions aloud, and a locally hosted language model asks follow-up questions based on what was said. Each answer is transcribed, analysed for vocal tone and delivery, and scored. At the end of the session the candidate receives written feedback, and the result is stored in MongoDB.

All speech recognition, emotion analysis and question generation run on the local machine. No paid AI API is used.

## Features

- Voice-based interviews: answers are recorded in the browser and the interviewer replies with synthesised speech.
- Follow-up questions generated by Llama 3 from the current question, the candidate's answer and the interview history.
- Selectable domain (nine are offered), difficulty (easy, medium, hard) and mode (3D avatar or audio wave only).
- Five questions per interview. The first question is chosen from a fixed set for the selected domain.
- Speech emotion recognition on each answer.
- Confidence, communication and overall scores for each interview.
- Written feedback generated at the end of the interview.
- User accounts with token-based authentication, a profile page and an interview history.
- A 3D interviewer with lip sync, blinking, head movement and distinct listening, thinking and speaking poses.

## How it works

1. The browser records the candidate's answer and uploads it to the Flask server.
2. FFmpeg converts the recording to 16 kHz mono WAV.
3. Whisper transcribes the audio. An empty transcript is treated as silence and is not scored.
4. A wav2vec2 classifier labels the vocal emotion, and Librosa measures duration and speech activity.
5. The server computes the scores for the answer.
6. Ollama runs Llama 3 to produce the next question. If Ollama is unavailable, a fixed fallback question is used.
7. The macOS `say` command synthesises the question, and FFmpeg converts it to WAV.
8. The browser plays the audio. In avatar mode the audio is routed through a Web Audio analyser that drives the avatar's mouth.
9. After the fifth answer the server returns a closing message. The browser then requests the final feedback, and the result is saved to MongoDB.

Interview state (current question, turn history, scores) is held on the server in a session document. The client does not submit scores, so they cannot be altered from the browser.

## Requirements

- macOS. The text-to-speech step calls the `say` command (see [Known limitations](#known-limitations)).
- Python 3.9 or later (the code has not been tested on earlier versions).
- FFmpeg available on the `PATH`.
- MongoDB listening on `localhost:27017`.
- Ollama with the `llama3` model pulled.
- A modern browser with microphone access and WebGL support.
- An internet connection on first run, to download the Whisper and wav2vec2 weights, and whenever the page loads Three.js, Tailwind and Lucide from their CDNs.

## Running the application

Start MongoDB and Ollama, then run the two servers below in separate terminals.

Backend (listens on `http://127.0.0.1:5000`):

```bash
python app.py
```

The first start downloads the model weights and may take several minutes. The backend is ready when it prints `Model Ready!`.

Frontend (static files on port 8000):

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000` in a browser.

The page must be served over HTTP. Opening `index.html` directly from the file system prevents the browser from loading `avatar.js` and the model.

## Using the application

1. Create an account, or log in.
2. Choose a domain, difficulty, language and mode, then start the interview.
3. Listen to the question. Select the microphone to begin recording and select it again to stop. Recordings shorter than two seconds are discarded.
4. Select **Submit Answer** to send the recording. Submit becomes available three seconds into a recording, and pressing it while recording stops the recording and sends it.
5. Repeat until the interview ends. The feedback screen then shows the scores, the dominant vocal tone and the written feedback.
6. Past interviews are listed under the history view, and summary statistics appear on the profile page.

An interview can be ended early from the interview screen. Only answers already submitted are scored.

## Configuration

There are no environment variables. Settings are constants near the top of `app.py` and `script.js`.

| Setting | File | Default |
| --- | --- | --- |
| Questions per interview (`MAX_QUESTIONS`) | `app.py` | `5` |
| Token lifetime (`TOKEN_TTL_HOURS`) | `app.py` | `12` hours |
| Generated audio retention (`FILE_MAX_AGE_SECONDS`) | `app.py` | `3600` seconds |
| Ollama endpoint and model (`OLLAMA_URL`, `OLLAMA_MODEL`) | `app.py` | `http://localhost:11434/api/generate`, `llama3` |
| MongoDB connection | `app.py` | `mongodb://localhost:27017/`, database `intraview_db` |
| Backend address (`API_BASE`) | `script.js` | `http://127.0.0.1:5000` |

MongoDB collections: `users`, `history`, `sessions` and `tokens`. Expired tokens are removed by a TTL index.

## Scoring

Scores are heuristic measures of delivery. They do not evaluate whether an answer is technically correct.

For each answer the server calculates four components, each from 0 to 100:

- **Pace**: 100 for 110 to 170 words per minute, reduced outside that range.
- **Filler words**: reduced as the proportion of fillers such as "um", "uh" and "you know" increases.
- **Voice**: based on the proportion of the recording that contains speech, with a small penalty for very quiet audio.
- **Emotion**: a fixed value for the detected vocal tone (for example 80 for Professional and 50 for Tense).

```
confidence    = 0.40 * pace + 0.30 * filler + 0.30 * emotion
communication = 0.35 * pace + 0.35 * filler + 0.30 * voice
```

Answers shorter than ten words are scaled down. The overall score is the mean of the confidence and communication scores. The scores for an interview are the averages across its answered questions.

The wav2vec2 model returns four labels (neutral, happy, angry, sad), which the interface displays as Professional, Enthusiastic, Tense and Subdued.

## API reference

All routes except `/`, `/signup`, `/login` and `/audio/<id>` require an `Authorization: Bearer <token>` header.

| Method | Route | Purpose |
| --- | --- | --- |
| POST | `/signup` | Create an account |
| POST | `/login` | Authenticate and receive a token |
| POST | `/logout` | Invalidate the current token |
| POST | `/start-interview` | Create a session and return the first question |
| POST | `/process-audio` | Submit an answer; returns the transcript, scores and next question |
| POST | `/end-interview` | Finalise the session, generate feedback and save the result |
| GET | `/get-profile/<username>` | Profile and summary statistics |
| GET | `/get-history/<username>` | Saved interviews, newest first |
| GET | `/audio/<id>` | Generated interviewer audio |

## Customising the avatar

The settings at the top of `avatar.js` (the `CFG` object) control the framing and behaviour of the 3D interviewer without further code changes.

| Setting | Effect |
| --- | --- |
| `distance`, `lookAtOffset` | Camera distance and aim |
| `tableDrop`, `tableBack` | Height and position of the table |
| `armDown`, `armForward`, `elbowBend`, `handsIn` | Arm pose, in degrees |
| `lipGain`, `silence`, `jaw`, `mouth`, `viseme` | Lip-sync sensitivity and mouth movement |
| `sway`, `nodSign` | Head movement amount and nod direction |

The model must contain ARKit-style blend shapes (`jawOpen`, `eyeBlinkLeft` and so on), Oculus-style visemes (`viseme_aa`, `viseme_O` and so on) and bones named `Head`, `Neck`, `Spine`, `Spine1`, `Spine2`, `LeftArm`, `LeftForeArm` and the right-hand equivalents. Blend shapes that are missing are skipped.

The avatar audio is routed through an `AudioContext`, so the interviewer audio is requested with `crossOrigin = 'anonymous'`. The backend's CORS configuration must therefore remain enabled for the frontend origin.

If WebGL or the model fails to load, the interface reports the error and uses the audio wave instead.

## Known limitations

- **Text to speech is macOS-only.** The `say` command is not available on Linux or Windows. If synthesis fails, the browser's built-in speech synthesis is used instead and the avatar's mouth follows a timed pattern rather than the audio. Replacing the synthesis function in `app.py` with a cross-platform engine would remove this restriction.
- **English only.** The language selector offers English, and the backend maps only English to a Whisper language code.
- **Lip sync is approximate.** It follows loudness and the spectral balance of the voice, not phonemes.
- **Scores measure delivery, not correctness.** They should be read as practice indicators.
- **Emotion recognition is coarse.** The classifier has four classes and was not trained on interview speech.
- **Development server.** The backend runs on Flask's built-in server. Use a production WSGI server and HTTPS before exposing it beyond a local machine.
- **Single-machine design.** Model inference is serialised with a lock, so concurrent users will queue.
- **Online dependencies.** Tailwind, Lucide and Three.js load from CDNs. Running fully offline requires hosting those files locally.
- **Local MongoDB without authentication** is assumed. Configure access control for any shared deployment.
